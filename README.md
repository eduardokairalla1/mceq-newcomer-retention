## Research question

Do newcomers who join open source projects through contribution events (Google Summer of Code, LFX Mentorship, Hacktoberfest, 24 Pull Requests) stay active for a different length of time than organic newcomers to the same project?

- **Design:** observational, matched-pair. Unit of analysis = pair (event-based newcomer, matched organic newcomer from the same project).
- **Dependent variable:** activity duration, in months, between first and last contribution to the project.
- **Sample:** 2001 pairs (4002 contributors) across 330 repositories. The primary analysis leaves out 65 pairs in which both members are the same GitHub account (n = 1936); a sensitivity analysis uses all 2001 pairs. See `PROTOCOL.md`, Amendment 1.

The pre-registered analysis plan (hypotheses, tests, effect sizes, threats to validity) is in [`PROTOCOL.md`](PROTOCOL.md).

### `data/processed/pairs.csv`

One row per pair:

| Column | Description |
|--------|-------------|
| `pair_id` | `contributor_id` of the event-based newcomer (the organic member's ID is this plus `__organic`) |
| `repo` | GitHub repository (`owner/name`), shared by both members |
| `event_type` | `gsoc`, `lfx`, `hacktoberfest` or `24pr` |
| `mentorship` | `True` for gsoc and lfx, `False` for hacktoberfest and 24pr |
| `duration_event` | Activity duration of the event-based newcomer (months) |
| `duration_organic` | Activity duration of the organic newcomer (months) |
| `D` | `duration_event − duration_organic` |
| `self_matched` | `True` when both members are the same GitHub account (same username, case-insensitive); these pairs are left out of the primary analysis |

## Reproducing from scratch

Requires Python 3.12. Both ways below install the exact versions from `uv.lock`.

**With [uv](https://docs.astral.sh/uv/getting-started/installation/)** (recommended; uv also installs Python 3.12 if needed):

```bash
git clone <repository-url> mceq-newcomer-retention
cd mceq-newcomer-retention

uv sync                                            # create .venv with the locked dependencies

uv run python src/prepare_data.py                  # build and validate data/processed/pairs.csv

uv run jupyter notebook notebooks/analysis.ipynb   # then: Kernel → Restart & Run All
# or, non-interactively:
uv run jupyter nbconvert --to notebook --execute --inplace \
  --ExecutePreprocessor.record_timing=False notebooks/analysis.ipynb
```

**With pip:**

```bash
git clone <repository-url> mceq-newcomer-retention
cd mceq-newcomer-retention

python3.12 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

python src/prepare_data.py
jupyter nbconvert --to notebook --execute --inplace \
  --ExecutePreprocessor.record_timing=False notebooks/analysis.ipynb
```

`requirements.txt` is generated from the lock file with `uv export --no-hashes --format requirements-txt > requirements.txt`; regenerate it whenever `uv.lock` changes.

Running the notebook writes the figures in `figures/` (PNG at 300 dpi and PDF, one ACM column wide) and `results/results.json`. The bootstrap uses a fixed seed, so the results are identical on every run; `record_timing=False` keeps run timestamps out of the notebook, so re-running it leaves the file unchanged.

`prepare_data.py` prints each check as `ok` or `FAIL` (2001 pairs, every contributor paired, 0 duplicated IDs, 0 missing durations, 330 repos, both pair members in the same repo, expected counts per event type) and stops with an `AssertionError` listing the failed ones. It then reports how many pairs are self-matched. Its output is deterministic.
